# DB 담당자 전달용 — 기획 결정사항 요약 (2026-08-14)

> 이 폴더는 DB 스키마 문서가 아닙니다. DB 코드/스키마 자체는 이 작업 환경에서 확인할 수 없어 직접 검토하지 못했으므로, **기획 논의 결과 중 DB 설계에 영향을 줄 만한 내용만 요약**했습니다. 실제 스키마 설계/마이그레이션은 DB 담당 개발자 판단에 따라주세요.

## DB 설계에 참고할 결정사항

1. **멀티테넌시 불필요(현재 범위)**: 이번 생애주기는 SAM 단일 극단 전용입니다. 추후 SaaS 확장 시 여러 극단을 구분하는 테넌트 개념이 필요해질 수 있으나, 지금 단계에서 미리 `tenant_id` 등을 넣는 과설계는 불필요합니다. 확장 시점에 마이그레이션으로 대응하는 편이 낫습니다.
2. **출석(쇼업) 체크 신규 테이블 필요**: 관리자 대시보드에 출석 체크 기능을 추가하기로 확정되었습니다. 신청(application) 레코드에 대해 실제 참석 여부/체크 시각/체크한 관리자를 기록할 테이블 또는 컬럼 확장이 필요합니다. (예: `applications` 테이블에 컬럼 추가, 혹은 별도 `attendance` 테이블 — 서버 담당자와 협의해서 결정)
3. **예매/결제 관련 테이블은 아직 착수하지 마세요**: 정책(취소/환불/알림)이 미확정이라 스키마를 먼저 만들면 재작업 가능성이 높습니다. 정책 확정 후 설계하는 것을 권장합니다.
4. **갤러리 이미지 저장 방식 미정**: 관리자가 업로드하는 방식이라면 이미지 메타데이터(업로드일, 업로더, 공연 연결 여부 등)를 위한 테이블이 필요할 수 있습니다. 업로드 방식이 확정되면 함께 설계 필요.
5. **인스타그램 연동 토큰 저장**: Graph API 액세스 토큰/리프레시 토큰을 저장할 안전한 저장소(암호화된 컬럼 또는 별도 시크릿 스토어)가 필요합니다 — DB에 평문 저장 금지.

## 아직 확정되지 않은 사항

- 기능명세서, 서비스 정책서 모두 논의 중입니다. 이 문서 기준으로 스키마를 확정하지 마시고, 서버 담당자의 `server/README.md` 및 원본 Notion 문서를 함께 참고해주세요.
